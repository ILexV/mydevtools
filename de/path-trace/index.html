Über den Agenten und Download
  1. Starte MyDevTools Agent. Unter Linux braucht ICMP den Ping-Gruppenbereich oder CAP_NET_RAW.
  2. Kopiere den Kopplungscode aus dem Agentenfenster.
  3. Füge den Code unten ein. Erlaube lokalen Netzwerkzugriff, wenn der Browser danach fragt.

Private, Loopback- und LAN-Ziele sind standardmäßig gesperrt. Aktiviere „Allow local network and this PC as targets“ im Agentenfenster nur bewusst. Router auf dem Pfad werden auch mit privater Adresse angezeigt. Die Kopplung fügt icmp.trace hinzu und behält Fähigkeiten, die dieser Browser schon hat; einen Scanner gewährt sie nie.

Der Browser sendet Ziel und Probeneinstellungen nur an den Agenten auf 127.0.0.1. ICMP-Proben gehen vom Agenten ins Netz, daher können Ziel und Router diesen Computer sehen. MyDevTools-Server erhalten weder Ziel noch Tabelle. Dieser Browser merkt sich letzte Ziele und diese Einstellungen. Hop-Ergebnisse und den Code speichert er nicht.

Pfadverfolgung sendet fortlaufende ICMP-Echo-Proben vom lokalen MyDevTools-Agenten und zeigt Verlust und Laufzeit jedes Hops. Der Browser sendet selbst kein ICMP. icmp.trace wird getrennt von http.request gewährt.

Detaillierte Funktionalität

Die Tabelle aktualisiert sich während der Verfolgung. Jeder Hop zeigt gesendete und empfangene Pakete, Verlust sowie letzte, beste, mittlere und schlechteste Laufzeit, die Standardabweichung und der mittlere Jitter. Ein stiller Hop zeigt „Keine Antwort“ und lässt die Adresse leer. Eine Router-Antwort bleibt sichtbar, auch ein Heim-Gateway oder eine CGNAT-Adresse aus 100.64.0.0/10. Das sind Beobachtungen des Pfads, keine neuen Ziele. Die eingegebene Adresse wird extra geprüft: private und Loopback-Ziele brauchen „Allow local network and this PC as targets“ im Agentenfenster, Metadata, Link-local und Multicast bleiben verboten. Proben enden am Ziel oder wenn sich derselbe Router am Ende wiederholt. Die Tabelle lässt sich als Text oder HTML kopieren und herunterladen. Der Agent schreibt den Bericht nicht auf die Platte. Letzte Ziele und Einstellungen bleiben in diesem Browser. Hop-Ergebnisse werden nicht gespeichert.

Praktische Beispiele

  • 1.1.1.1 verfolgt einen öffentlichen Resolver mit 64 Byte Nutzlast, 30 Hops und 5 Sekunden Probe-Zeitlimit.
  • example.com wird über das DNS des Computers aufgelöst, danach wird nur die erste Adresse geprüft.
  • 127.0.0.1 braucht „Allow local network and this PC as targets“ im Agentenfenster.

So verwenden Sie dieses Tool

  1. 1

    Lokalen Agenten starten

    Lade den Agenten herunter, starte ihn und kopiere den Code. Unter Linux braucht ICMP den Ping-Gruppenbereich oder CAP_NET_RAW.

  2. 2

    Pfadverfolgung koppeln

    Füge den Code ein und verbinde. Die Seite fordert icmp.trace an und behält Fähigkeiten, die dieser Browser schon hat, etwa http.request.

  3. 3

    Einen Host verfolgen

    Gib einen Hostnamen oder eine IP ein, passe Intervall, Nutzlast, Hop-Grenze und Zeitlimit bei Bedarf an und drücke Start. Stopp beendet die Proben. Der letzte Schnappschuss bleibt auf der Seite.

  4. 4

    Bericht kopieren

    Wähle einen Hop, um den ICMP-Status zu lesen. Kopiere oder lade die Tabelle als Text oder HTML herunter.

Tipps und Best Practices

  • Der Verlust ist eine ganze Zahl. Vor der ersten Probe ist er 0. Danach ist er 100 minus 100 mal empfangen geteilt durch gesendet.
  • Eine fehlende Laufzeit ist ein Strich, keine Null.
  • Standardabweichung und mittlerer Jitter erscheinen nach zwei Antworten, auf Zehntel Millisekunden. Ein Timeout ist keine Stichprobe. Jitter ist der laufende Mittelwert der absoluten Differenz aufeinanderfolgender Antworten.
  • Schalte die Namensauflösung aus, damit in der Host-Spalte die numerische Adresse steht.
  • Der Agent führt höchstens zwei Verfolgungen gleichzeitig aus. Jedes Desktop-Fenster startet eine eigene.
  • Der veröffentlichte Windows-Download kann älter sein als diese Seite. Die Verfolgung braucht einen Agenten, der icmp.trace anbietet.
  • Path-MTU suchen sendet DF-Proben und behält die größte Größe, die ein Echo erhält. Eine verlorene Probe ist keine Größengrenze. Die Suche endet bei 1500 Bytes.
  • Quelle listet die Adressen dieses Computers. Automatisch überlässt die Wahl dem System. Die Liste ist kein Scan und keine ARP-Tabelle.
