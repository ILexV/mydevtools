## Найденные и исправленные баги

### Изображения (`qa-files`)
1. **Конвертер: GIF, BMP, ICO, TIFF и TGA всегда давали ошибку `Unsupported target format`.** В крейте `image` были включены только `png/jpeg/webp`, хотя инструмент предлагает 8 форматов. Подтверждено в браузере на старом WASM. Исправлено в `wasm/image_tools/Cargo.toml` (фичи) и `wasm/image_tools/src/lib.rs` (ветки кодирования):
   - ICO больше 256 px уменьшается с сохранением пропорций;
   - 16-битные и float-источники приводятся к 8 бит.
   - Размер WASM: 958 KB → 1576 KB (gzip ≈ 482 KB), грузится только на страницах image-инструментов.
2. **JPEG из PNG с прозрачностью**: альфа-канал отбрасывался, прозрачные области становились чёрными или цвета фона пикселя. Теперь изображение накладывается на белый фон (`flatten_on_white`).
3. **Ресайзер: отрицательный размер** (`-5`) проходил проверку `!width`, а в WASM превращался в u32 около 4·10⁹. Итог — попытка гигантского выделения памяти и падение вкладки. Теперь размеры проверяются и в контроллере (`parseResizeDimensions`: только целые > 0, ≤16384 px по стороне, ≤64 МП), и в Rust (`validate_dimensions`).
4. **Вся обработка изображений шла в основном потоке**: большие файлы замораживали страницу, отменить было нельзя. Сделано:
   - новый worker `src/workers/image-tools.worker.ts` и протокол `src/scripts/wasm/image-tools-protocol.ts`;
   - `image-tools-client.ts` переписан на worker с `AbortSignal`: отмена убивает worker, следующий вызов создаёт новый; при падении WASM (OOM) worker тоже пересоздаётся.
   - Во всех трёх инструментах есть `Progress` с кнопкой отмены. Проверено: при 6000×4000 и 8000×8000 страница отзывчива (evaluate ≈ 2 мс), отмена работает, повторный запуск после отмены успешен.
5. **Scoped `display:flex` перекрывал атрибут `hidden`** у контейнера превью в конвертере: превью TIFF/TGA оставалось битой картинкой. Добавлено правило `[hidden]`.
6. **Input файла был скрыт атрибутом `hidden`** и недоступен с клавиатуры. Заменён на `FileDrop`; проверено, что при Tab кольцо фокуса 2px solid на кнопке.
7. **Ошибки WASM показывались сырым английским текстом.** Теперь сначала идёт локализованный префикс («Сжатие не удалось.» и т. п.), затем техническая деталь. Неподдерживаемые форматы (SVG/AVIF/HEIC) отсекаются до WASM с локализованным сообщением.
8. **Мелочи:**
   - пропущены пробелы в «Original:3.11 KB→Compressed:» и «Output Size:»;
   - повторный выбор того же файла;
   - собственные `formatBytes` заменены на `formatBytes(b, 2)` из `@/lib/format`; вывод тот же, кроме байтов: «238 B».

### PDF (ветка PDF)
1. **Подтверждена гипотеза foundation**: строки `pdfc-*`/`pdft-*`, создаваемые контроллером, были без стилей. Теперь `ds-file-item*` и `:global()` внутри корня инструмента; DOM строит `src/tools/pdf-file-ui.ts`.
2. **`wasm/pdf/src/lib.rs`, извлечение текста:**
   - в каждый .txt попадал блок `=== DEBUG: Page N … First 20 mappings ===`;
   - несжатые потоки давали пустой текст (`decompressed_content()` возвращает ошибку без фильтра);
   - ToUnicode из унаследованных от `/Pages` ресурсов игнорировался.
3. **Зашифрованные PDF открывались без расшифровки**: сжатие молча выдавало испорченный файл, merge и извлечение давали мусор. Теперь пробуется пустой пароль, иначе стабильная ошибка «PDF is encrypted» и локализованное сообщение.
4. **Merge**: `/Parent` вставленных страниц указывал на дерево исходного документа. Страницы переподчинены, MediaBox/Resources/CropBox/Rotate скопированы на страницу.
5. **Одна ошибка обрывала весь пакет.** Теперь у такой строки бейдж ошибки, остальные файлы обрабатываются. Сырые ошибки Rust заменены локализованными с именем файла.
6. В compressor и to-text добавлена отмена между файлами. В merger добавлены ↑/↓. Input был `hidden` — заменён на `FileDrop`.

### QR (ветка QR)
1. **Стили «точки» и «скруглённые» давали QR, которые наш же сканер (rxing) не читал**: 7 из 12 комбинаций стиль × уровень коррекции. Причина: поисковые квадраты 7×7 тоже рисовались точками. Теперь они всегда квадратные, читаются все 12 комбинаций, в том числе при 256 px (`wasm/qrcode/src/lib.rs`).
2. **Паника WASM на однотонных картинках меньше 40 px** (`unwrap` внутри rxing). Теперь картинка дополняется до 40 px → «QR не найден».
3. **Разбор hex-цвета** мог паниковать на не-ASCII, а SVG вставлял цвета без проверки. Добавлена валидация и ошибка «размер слишком мал».
4. **Контроллеры:**
   - локализованы ошибки WASM;
   - невалидный hex больше не игнорируется молча;
   - логотип GIF/SVG больше не показывается в превью без попадания в QR;
   - устранено перекрытие `hidden` scoped-`display`;
   - в сканере устранена гонка, когда старый результат затирал новый;
   - добавлена ошибка копирования;
   - input `hidden` заменён на доступный с клавиатуры.

## Открытые вопросы

- **WebP в image_tools только lossless** (энкодер image-rs): ползунок качества на WebP не влияет, и JPEG-фото в WebP обычно растёт. Lossy WebP требует libwebp (C) в WASM — отдельное решение.
- **PDF и QR WASM работают в основном потоке**: большой PDF или картинка ~3800 px блокируют UI (QR — около 1,2 с). Отмена PDF возможна только между файлами. Кандидаты на перенос в worker по образцу `image-tools.worker.ts`.
- **TIFF/TGA на входе ресайзера**: браузер не может их декодировать, размеры неизвестны → «Не удалось загрузить изображение» (паритет с legacy). Конвертер и компрессор такие файлы принимают.
- **pdf-to-text** по-прежнему игнорирует операторы `'`/`"` и переводы строк по `Td`/`T*` (паритет); остался старый warning `unused font_map`.
- **Сканер** использует `MultiFormatReader` (все типы штрихкодов, паритет). Можно ограничить только QR.
- **Генератор** при 512 px отдаёт картинку чуть меньше, кратно размеру модуля (паритет).
- **Ветка PDF сообщила**, что её файлы (`pdf-file-ui.ts`, `PdfCompressor.astro`, `pdf-merger.client.ts`, `pdf-to-text.client.ts`) менялись на диске после её правок. Скорее всего, это её же записи; финальный функциональный прогон прошёл после этого. Стоит проверить диффы при сведении.

## Запросы к общему слою (`foundation`)

Группа `files` — первый реальный пользователь `FileDrop`, `ds-file-item*` и `bindDropzone`. В целом они работают: `.is-dragover`, drop через DataTransfer, клик по фону зоны, кольцо фокуса на `.ds-file-btn`, `aria-disabled` во время работы.

1. **`bindDropzone` не сбрасывает `input.value`**: повторный выбор того же файла не вызывает `change`. Все три подгруппы сбрасывают значение сами. Предлагается сбрасывать после `onFiles` в хелпере или описать это в `tool-ui-kit.md`.
2. **`.ds-file-item-name` — `nowrap` + ellipsis**: на 375 px длинное имя не прочитать (мы ставим `title`, на тач-экране он не виден). Нужен модификатор с переносом (`overflow-wrap:anywhere`) или перенос по умолчанию — это прямо требует чек-лист.
3. **У `FileDrop` подпись кнопки фиксированная**: нет хука, чтобы поменять «Выбрать файл» на «Выбрать другой файл» в выбранном состоянии. Нужен `labelProps` на текстовом `<span>` или проп `changeLabel`.
4. **`Progress`**: нет пропа `indeterminate`. `barProps.class` перезаписал бы `ds-progress`, поэтому `is-indeterminate` ставим из контроллера. Предлагается `indeterminate?: boolean`.
5. **`.ds-result-row` рассчитан на 3 колонки** (ключ, значение, кнопка); для информационных строк без кнопки пришлось локально задавать `grid-template-columns`. Нужен вариант на 2 колонки или `:not(:has(> button))`.
6. **`.ds-spinner` без `display:inline-block`**: внутри обычного `<span>` вне flex у него нулевой размер (сообщила ветка PDF).
7. **`Field`**: нет способа задать `id` у hint для `aria-describedby` (ветка QR назначает его в контроллере).
8. **Предлагается дописать в документацию**: правило «`hidden` авторитетен» действует только для `ds-*`. Любой scoped-класс с `display:flex|grid` на элементе, который переключается через `hidden`, ломает скрытие — во всех трёх подгруппах это было реальным багом. Предлагается добавить в `tool-ui-kit.md` или сделать глобальным `[hidden]{display:none!important}`.
