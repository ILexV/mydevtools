# SEO-тексты инструментов: правила (2026-10-06)

Ключи в `apps/site/src/i18n/locales/<lang>/tools/<slug>.json`, рендер — `components/ToolSeoContent.astro` (видимый блок) и `lib/seo.ts` (JSON-LD, HowTo из `Seo_HowToSteps`).

## Принципы
- **Правда о реализации.** Перед написанием прочитать код инструмента (`src/tools/<Name>.astro`, `<slug>.client.ts`, WASM-клиент, `registry/tools.ts` capabilities). Упоминать WebAssembly/Rust только если инструмент реально грузит WASM; «файлы» — только если есть файловый ввод; «настройки сохраняются» — только если есть localStorage; офлайн — сайт имеет service worker (network-first для страниц): можно писать «после первого открытия страница работает и без сети», не обещать большего.
- **Конкретика вместо воды.** Никаких «comprehensive functionality», «modern web technologies», «improved productivity». Каждый текст уникален для инструмента: что делает, какие форматы/алгоритмы/опции, ограничения, типичные задачи разработчика.
- Без keyword stuffing, без конкурентов, без непроверяемых превосходных степеней.

## Ключи
- `Seo_Introduction` — 1–2 предложения (≈150–300 символов): что это и чем полезно.
- `Seo_DetailedDescription` — 2–3 абзаца (разделитель `\n\n`): возможности, поддерживаемые форматы/алгоритмы/опции, ограничения, приватность по существу.
- `Seo_Examples` — 3–4 примера: `**Заголовок**: текст`, с реальными входами/выходами в `` `inline code` `` (проверить, что результат действительно такой — прогнать в инструменте).
- `Seo_HowToSteps` — 3–5 шагов строго в формате `### <Слово-шаг> N: <Название>\n<тело>` (слово как в текущей локали: Step/Шаг/Paso/Schritt/Passo/步骤/Étape/ステップ/단계/चरण; ko — `### 1단계: …`, zh — `### 步骤1：…`). Названия кнопок/полей — ровно как в UI этой локали.
- `Seo_Tips` — 4–6 пунктов `- …`: практичные советы и подводные камни.
- `Title` (≤ 60 симв., это и H1) — менять только если неточно. `Description` (≈120–160 симв.) — точное описание для meta. `Keywords` — релевантные, через запятую.

## Разметка
Поддерживается только: абзацы через пустую строку, `**bold**`, `` `code` ``, списки `- `, заголовки `###` (только в HowTo). Ссылки/HTML не использовать.

## Языки
Писать сначала en, затем естественные (не дословные) переводы для ru, es, de, pt, zh (упрощённый), fr, ja, ko, hi (деванагари). Технические термины (Base64, SHA-256, JSON, UUID, JWT, PEM) не переводить.

## Проверка
`flock /tmp/mydevtools-tests.lock npm run validate:i18n -w @mydevtools/site`; в браузере на dev-сервере — SEO-блок en/ru/ja/hi читается (шрифты CJK/деванагари установлены), JSON-LD HowTo содержит столько же шагов, сколько в тексте (`document.querySelectorAll('script[type="application/ld+json"]')`).
