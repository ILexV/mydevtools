HTTP Client

Send HTTP requests from your Windows machine through a local companion, with no account or MyDevTools proxy.

Requests go directly from your Windows machine to the target

Saved requests

Keeps the last 100 sent requests as written — variables and secrets stay unresolved, responses are not kept. Stored where the workspace is.

    i Drag items into folders or blank space to move them to the root. Right-click or press Shift+F10 to open actions.

    Secrets

    Values stay in the agent's encrypted vault and never come back to the page. Put {{secret:name}} into the URL, a header or the body: the agent substitutes it only for the listed hosts and hides it in the response.

      Environments

      Use {{name}} in the URL, params, headers, body and auth. The active environment overrides folder variables, and those override globals. For a write-only value, set the variable to {{secret:name}}.

      Client settings

      Proxy

      The agent connects through an HTTP proxy: CONNECT for https, absolute URLs for http. The proxy password is saved with the workspace.

      Client certificates (mTLS)

      The agent presents a certificate to https hosts in its list when the server asks for one. The private key is stored encrypted in the agent and never returns to the page. Use PEM files with an unencrypted key; convert a .pfx first: openssl pkcs12 -in cert.pfx -out cert.pem -nodes

      Connect an agent with the secrets vault to add client certificates.

                        Send HTTP and HTTPS requests without creating an account or routing API credentials through a MyDevTools server. A small companion running on your Windows computer performs the network request and returns status, timing, headers and the response body to this page.
                        Detailed Functionality
                        The browser pairs explicitly with the companion on 127.0.0.1 using a short-lived one-time code. It stores the resulting session token in this browser for up to 8 hours or until the agent restarts; the code is not stored. The token grants only the http.request capability. Requests go from the companion directly to the target. Public targets are allowed by default; private, loopback and LAN addresses require turning on “Allow local network and this PC as targets” in the agent window (or the --allow-private startup option). Redirects are off by default and sensitive headers are removed when a redirect changes origin. Request drafts, including URLs, headers and secrets, and bodies are saved automatically in this browser so they reopen later; responses are not saved. The connection token is stored separately for up to 8 hours or until the agent restarts. With a current agent, drafts are kept encrypted on the computer by the agent instead of the browser.
                        Practical Examples
                        Use GET to inspect a JSON endpoint, POST with Content-Type: application/json to test an API payload, or HEAD to inspect response metadata without a body. Add Authorization: Bearer … only when the target API requires it; it is sent to that target, not to MyDevTools servers.
                        How to Use This Tool
                        1. 1
                          Install and start the companion
                          Download the Windows x64 companion and launch it.
                        2. 2
                          Pair explicitly
                          Request a code in the companion window, enter it here and click Connect. The code is cleared immediately after the attempt.
                        3. 3
                          Compose the request
                          Choose a method, enter an HTTP or HTTPS URL, then add optional headers and a raw UTF-8 body.
                        4. 4
                          Send and inspect
                          Send the request to view native status, timing, final URL, duplicate-preserving headers and a safe text preview. Download binary bodies byte-for-byte.
                        Tips and Best Practices
                          

                        • Keep redirects off when you need to inspect the first response.
                          • 

                        • Credentials in an Authorization header go to the target service; avoid sharing screenshots that contain them.
                          • 

                        • Leave private-network access disabled unless you deliberately test a trusted LAN service.
                          • 

                        • Pairing this tool never authorizes future port or network scanning capabilities.
