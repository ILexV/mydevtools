HTTP クライアント

Windows のローカルエージェントから HTTP リクエストを送信します。アカウントも MyDevTools プロキシも不要です。

リクエストは Windows PC から送信先へ直接送られます

保存済みリクエスト

送信したリクエストを書いたままの形で直近 100 件保存します。変数やシークレットは展開されず、レスポンスは保存されません。ワークスペースと同じ場所に保存されます。

    i 項目をフォルダーにドラッグするか、空白部分にドラッグしてルートへ移動します。右クリックまたは Shift+F10 で操作メニューを開きます。

    リクエスト URL、ヘッダー（シークレットを含む）、本文はこのブラウザーにのみ自動保存されます。レスポンスは保存されません。

    フォルダーに移動

    シークレット

    値はエージェントの暗号化ストレージに保存され、ページに戻ることはありません。URL、ヘッダー、ボディに {{secret:name}} を入れると、エージェントは指定したホストに対してのみ置き換え、レスポンスでは隠します。

      シークレットはまだありません。

      シークレットを追加

      環境

      URL、パラメーター、ヘッダー、ボディ、認証で {{名前}} を使えます。有効な環境はフォルダー変数より、フォルダー変数はグローバル変数より優先されます。書き込み専用の値には変数を {{secret:名前}} に設定します。

      クライアント設定

      プロキシ

      エージェントは HTTP プロキシ経由で接続します。https には CONNECT、http には絶対 URL を使います。プロキシのパスワードはワークスペースと一緒に保存されます。

      クライアント証明書 (mTLS)

      サーバーが求めたとき、エージェントはリストにある https ホストへ証明書を提示します。秘密鍵はエージェント内に暗号化して保存され、ページには戻りません。暗号化されていない鍵の PEM ファイルを使ってください。.pfx は先に変換します: openssl pkcs12 -in cert.pfx -out cert.pem -nodes

      クライアント証明書を追加するには、シークレット保管庫のあるエージェントに接続してください。

        クライアント証明書はまだありません。

        証明書を追加

        保存済みの証明書と鍵を残すには、両方のファイルを空のままにします。

        Cookie

        レスポンスの Cookie はここに入り、条件に合うリクエストで送られます。エージェントはリダイレクトを含む各ホップで、ドメイン・パス・Secure をもとに選びます。「Cookie を保持」がオフなら、ページを閉じるまで有効です。

          Cookie はまだありません。

          Cookie を追加

          認証

          変数

          このフォルダーとサブフォルダーのすべてのリクエストで {{名前}} として使えます。近いフォルダーが優先されます。

          スクリプト

          このフォルダーとサブフォルダー内のすべてのリクエストで、リクエスト自身のスクリプトより先に実行されます。

          データ

          リクエストはツリーの順にスクリプトとともに 1 件ずつ実行され、スクリプトが変更した変数は保存されます。データファイルがあると 1 行ごとに 1 イテレーションとなり、pm.iterationData と {{列名}} で参照できます。このウィンドウを閉じると実行は停止します。

          リクエスト

              cURL のインポート

              curl コマンドを貼り付けてください（ブラウザー DevTools の「Copy as cURL」、bash または cmd など）。新しいリクエストが作成されます。URL 欄に貼り付けたコマンドは、開いているリクエストを置き換えます。

              リクエストのコード

              開いているリクエストから生成します。変数は置換され、{{secret:…}} はプレースホルダーのまま、ファイルは名前で参照されます。AWS 署名と OAuth トークンの有効期間は限られています。

              ブラウザーはリクエスト情報を 127.0.0.1 のエージェントだけに送ります。エージェントは宛先に直接接続するため、URL、ヘッダー、本文は PC 外へ送られることがあります。MyDevTools サーバーは受信も中継もしません。URL、ヘッダー、シークレットを含むリクエストの下書きと本文はこのブラウザーに自動保存されますが、レスポンスは保存されません。接続トークンは別に最長 8 時間またはエージェントの再起動まで保存され、ペアリングコードは保存されません。エージェントが暗号化ストレージを提供すると、下書きはそちらへ移され、ブラウザーから削除されます。

              構文が強調表示されます。明示的に要求した場合のみ整形します。選択した形式が Content-Type を設定しますが、有効なヘッダーがある場合はそちらが優先されます。
              チェックした行は キー=値 の組として Content-Type application/x-www-form-urlencoded で送信されます（有効なヘッダーで上書きした場合を除く）。キーと値には {{変数}} を使えます。
              チェックした各行はテキストフィールドかファイルです。boundary 付きの Content-Type multipart/form-data は自動で設定され、手動の設定を置き換えます。 ファイルはこのページのメモリにだけ保持されます。再読み込み後は選び直してください。ファイル内の変数は置換されません。

                        アカウントを作らず、API 認証情報を MyDevTools サーバーに通さずに HTTP/HTTPS リクエストを送れます。Windows の小さなエージェントが接続し、状態、時間、ヘッダー、本文を返します。
                        詳細な機能
                        ブラウザーは使い捨てコードで 127.0.0.1 のエージェントと明示的にペアリングします。接続トークンはこのブラウザーに最長 8 時間、またはエージェントが再起動するまで保存され、コードは保存されません。トークンは http.request のみを許可します。リクエストは宛先へ直送されます。プライベートネットワークにはエージェントのウィンドウで「Allow local network and this PC as targets」をオンにする（または --allow-private）必要があり、リダイレクトは既定で無効、オリジン変更時は機密ヘッダーが削除されます。 URL、ヘッダー、シークレットを含むリクエストの下書きと本文は、後で再度開けるようこのブラウザーに自動保存されます。レスポンスは保存されません。接続トークンは別に最長 8 時間またはエージェントの再起動まで保存されます。最新のエージェントでは、下書きはブラウザーではなくエージェントがコンピューター上に暗号化して保存します。
                        実用例
                        JSON には GET、API には Content-Type: application/json 付き POST、メタデータには HEAD を使います。Authorization: Bearer … は必要な場合だけ追加し、MyDevTools ではなく宛先へ送られます。
                        このツールの使い方
                        1. 1
                          インストールして起動
                          Windows x64 エージェントをダウンロードして起動します。
                        2. 2
                          ペアリング
                          エージェント画面でコードを発行し、入力して 接続 を押します。
                        3. 3
                          リクエストを作成
                          メソッド、HTTP/HTTPS URL、ヘッダー、UTF-8 本文を入力します。
                        4. 4
                          送信して確認
                          状態、時間、最終 URL、ヘッダー、安全なテキストプレビューを確認し、バイナリは正確にダウンロードします。
                        ヒントとベストプラクティス
                          

                        • 最初のレスポンスを見るにはリダイレクトを無効にします。
                          • 

                        • Authorization は宛先に送られるため、秘密を含む画面を共有しないでください。
                          • 

                        • 信頼できる LAN サービス以外ではプライベートアクセスを有効にしないでください。
                          • 

                        • ペアリングは将来のポート・ネットワークスキャンを許可しません。
