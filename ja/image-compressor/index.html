JPEG・PNG・WebP 画像をブラウザ上で軽量化できます。品質を 1～100 で選び、出力形式を決めて、元のサイズと圧縮後のサイズを比べたら _min ファイルをダウンロードします。画像がアップロードされることはありません。

詳細な機能

圧縮は 1 枚ずつ再エンコードして行います。元のフォーマットを維持 を選ぶと JPEG は JPEG、PNG は PNG のまま保存され、それ以外の入力は WebP で保存されます。JPEG・PNG・WebP を明示的に指定することもできます。品質の効き方は形式ごとに異なります。JPEG はそのまま品質値を使い、PNG は 90 未満で 256 色パレットに減色され（90 以上はロスレスのまま）、WebP はブラウザが指定品質の非可逆圧縮でエンコードします。

再エンコードによって、カメラの機種や GPS 位置情報などの EXIF その他のメタデータは削除されます。EXIF の回転情報は先にピクセルへ反映されるので、スマートフォンの写真も向きが崩れません。JPEG で保存すると透明部分は白になります。ブラウザに非可逆 WebP エンコーダーがない場合（一部の Safari）はロスレス WebP が保存され、品質設定が適用されなかったことが表示されます。

圧縮は Rust/WebAssembly とブラウザ標準の WebP エンコーダーを使って Web Worker 内で実行されるため、大きな画像でもページは固まらず、キャンセル ですぐに中止できます。ファイルはローカルで読み込まれ、サーバーには送信されません。

実用例

写真を WebP に: 476.38 KB の 1920×1280 の JPEG を WebP・品質 80 にすると 186.58 KB（完了！ -61%）になり、photo_min.webp としてダウンロードされます。

JPEG を強めに圧縮: 同じ写真を JPEG・品質 60 にすると 167.27 KB（−65%）、既定の 80 では 396.49 KB（−17%）です。

スクリーンショット: 1280×800 の画面キャプチャ（126.47 KB の PNG）は WebP・品質 80 で 53.49 KB に、ロスレス PNG（品質 90）では 91.26 KB になります。

小さくならない場合: すでに最適化済みのファイルなどで結果が小さくならないときは、両方のサイズは表示されますが 完了！ バッジは表示されません。元のファイルを使ってください。

このツールの使い方

  1. 1

    画像を選ぶ

    ファイルを選択 をクリックするか、PNG・JPEG・WebP 画像をエリアにドロップします。ファイルサイズと寸法付きのサムネイルが表示されます。

  2. 2

    品質と形式を設定する

    品質 スライダー（既定 80%）を動かし、出力フォーマット で 元のフォーマットを維持、JPEG、PNG、WebP のいずれかを選びます。

  3. 3

    圧縮する

    画像を圧縮 をクリックします。時間のかかる処理は キャンセル で止められます。

  4. 4

    比較してダウンロードする

    元のサイズ: → 圧縮後: を確認し、ダウンロード をクリックして <name>_min.<ext> を保存します。

ヒントとベストプラクティス

  • 写真なら WebP か JPEG の品質 60～80 が最も効果的なことが多いです。スクリーンショットや透過のあるグラフィックは PNG のままにしましょう。
  • PNG は品質 90 未満で 256 色パレットに切り替わります。単色主体の図には向きますが、グラデーションに縞が出ることがあり、必ずしもファイルが小さくなるとは限りません。
  • 透過 PNG を JPEG で保存すると透明部分は白で塗りつぶされます。透過を残すなら PNG か WebP を選んでください。
  • GPS 座標を含む EXIF データは結果から削除されます。写真を公開する前に便利です。
  • ロスレス WebP についての注記が出た場合、そのブラウザは非可逆 WebP をエンコードできません。写真を小さくしたいときは JPEG を選んでください。
