経路追跡は、この PC の MyDevTools ローカルエージェントから ICMP エコーを連続して送り、各ホップの損失と遅延を表示します。ブラウザ自身は ICMP を送りません。icmp.trace は http.request とは別に許可されます。

詳細な機能

追跡中、表は更新されます。各ホップは送信数、受信数、損失、そして最新・最良・平均・最悪の往復時間、標本標準偏差、平均ジッタを記録します。沈黙したホップは「応答なし」と空のアドレスを示します。ルーターの応答は残り、家庭のゲートウェイや 100.64.0.0/10 の CGNAT アドレスも含みます。これらは経路の観測であり、新しい宛先ではありません。入力したホストは別に検査されます。プライベートとループバック宛先にはエージェントのウィンドウで「Allow local network and this PC as targets」をオンにする必要があり、メタデータ、リンクローカル、マルチキャストは常に拒否されます。プローブは宛先、または経路の末尾で同じルーターが繰り返された時点で止まります。現在の表はテキストまたは HTML としてコピーおよびダウンロードできます。エージェントはその報告をディスクに書きません。最近の宛先と間隔、ペイロード、ホップ上限、タイムアウト、名前解決の設定はこのブラウザに残ります。ホップ結果は保存しません。

実用例

  • 1.1.1.1 は 64 バイト、30 ホップ、5 秒のプローブ待ちで公開リゾルバを追跡します。
  • example.com はこの PC の DNS で解決され、最初のアドレスだけを探ります。
  • 127.0.0.1 にはエージェントのウィンドウで「Allow local network and this PC as targets」をオンにする必要があります。

このツールの使い方

  1. 1

    ローカルエージェントを起動する

    エージェントをダウンロードして起動し、コードをコピーします。Linux では ICMP に ping グループ範囲または CAP_NET_RAW が必要です。

  2. 2

    経路追跡をペアリングする

    コードを貼り付けて接続します。ページは icmp.trace を要求し、このブラウザが既に持つ機能（http.request など）を保ちます。

  3. 3

    ホストを追跡する

    ホスト名または IP を一つ入力し、必要なら間隔、ペイロード、ホップ上限、タイムアウトを調整して開始を押します。停止でプローブは終わります。最後のスナップショットはページに残ります。

  4. 4

    報告をコピーする

    ホップを選ぶと ICMP 状態が読めます。表をテキストまたは HTML としてコピーまたはダウンロードします。

ヒントとベストプラクティス

  • 損失は整数です。プローブ前は 0 です。その後は 100 から、100 かける受信を送信で割った値を引きます。
  • 往復時間がないときはゼロではなくダッシュです。
  • 標準偏差と平均ジッタは応答が二つ集まってから、0.1 ミリ秒単位で出ます。タイムアウトは標本になりません。ジッタは連続する応答の差の絶対値の移動平均です。
  • 名前解決を切ると、ホスト列は数値アドレスのままです。
  • エージェントが同時に走らせる追跡は最大二つです。デスクトップの各ウィンドウは自分の追跡を始めます。
  • 公開されている Windows 版は、このページより古いことがあります。経路追跡には icmp.trace を告知するエージェントが必要です。
  • パス MTU の検索は DF 付きプローブを送り、エコーが返った最大サイズを残します。失われたプローブはサイズ制限ではありません。検索は 1500 バイトで止まります。
  • 送信元はこのコンピュータ自身のアドレスです。自動は選択をシステムに任せます。一覧はスキャンでも ARP テーブルでもありません。
