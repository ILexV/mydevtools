ZIP

아카이브 탐색기

ZIP, TAR, TAR.GZ 및 Zstandard·Brotli 아카이브를 브라우저에서 열어 내용을 확인하고, 선택한 파일을 안전하게 추출하며, 새 ZIP 또는 TAR 아카이브를 만듭니다.

입력 내용과 파일은 브라우저 밖으로 전송되지 않습니다

아카이브

아카이브 파일

ZIP, TAR, TAR.GZ, TGZ, TAR.ZST, TAR.BR, GZ, ZST 또는 BR. 파일은 이 기기를 벗어나지 않습니다.

아카이브는 Web Worker에서 1 MiB 블록 단위로 읽고 WASM에서 압축을 풉니다. 아무것도 업로드되지 않으며 이름, 내용, 선택 항목은 저장되지 않습니다.

아카이브 처리 중

내용

아카이브를 선택하면 파일과 폴더 목록이 표시됩니다.

    행을 클릭하거나 Space 키를 눌러 선택합니다. 폴더를 선택하면 안의 모든 항목이 선택됩니다.

    추출

    무엇이든 기록하기 전에 경로를 검사합니다. 절대 경로, “..”, 드라이브 문자, 제어 문자는 건너뛰고, 링크는 만들지 않으며, 폴더에 같은 파일이 이미 있으면 기존 파일을 유지하고 새 파일에는 “ (2)” 이름을 붙입니다. 각 항목은 선언된 크기와 CRC-32가 일치해야 합니다.

    항목은 최대 1,000,000개, 중앙 디렉터리는 최대 256 MiB입니다. 데이터가 64 MiB를 넘어 1000배 이상 늘어나거나 출력이 64 GiB를 넘으면 추출이 중단됩니다. ZIP 방식: Stored, Deflate, Zstandard. 암호화된 항목은 열지 않습니다. 저장 대화 상자가 없는 브라우저(Firefox, Safari)에서는 다운로드가 512 MiB로 제한됩니다.

    아카이브 만들기

    압축할 파일

    끌어다 놓은 파일은 목록에 추가됩니다. “폴더 추가”는 폴더 구조를 유지합니다.

    아직 추가된 파일이 없습니다.

    ZIP은 UTF-8 이름과 Deflate를 사용하며 4 GiB 이상 파일에는 ZIP64로 전환합니다. TAR은 ustar 헤더를 사용하고 긴 이름이나 ASCII가 아닌 이름에는 pax를 사용합니다. TAR.GZ와 TAR.ZST는 전체 스트림을 압축합니다.

    아카이브 탐색기는 ZIP, TAR 및 압축된 TAR 아카이브(gzip, Zstandard, Brotli)를 브라우저에서 바로 엽니다. 모든 항목을 크기, 압축 크기, 날짜, 방식과 함께 보여 주고, 선택한 파일을 폴더나 새 ZIP으로 추출하며, 내 파일을 ZIP, TAR, TAR.GZ 또는 TAR.ZST로 묶습니다. 아무것도 업로드되지 않습니다.

    상세 기능

    ZIP은 중앙 디렉터리에서 읽으며 ZIP64 아카이브, 자동 압축 해제 스텁, Info-ZIP 유니코드 이름도 지원하므로 항목이 백만 개인 아카이브도 압축을 풀지 않고 열립니다. TAR 아카이브는 GNU 긴 이름과 pax 레코드를 포함해 헤더 단위로 읽고, 압축된 TAR은 Web Worker에서 한 번의 스트리밍 패스로 풉니다. Deflate, gzip, Zstandard, Brotli는 출력 창이 제한된 WASM에서 실행되므로 압축 폭탄도 한 번에 1 MiB 이상 부풀지 않습니다.

    추출은 경로 탐색 공격(Zip Slip)으로부터 보호됩니다. 절대 경로, 드라이브 문자, “..” 세그먼트, 제어 문자는 절대 기록되지 않고, 심볼릭 링크와 하드 링크는 만들지 않으며, Windows가 거부하는 문자나 장치 이름은 바꿉니다. 각 항목은 선언된 크기와 CRC-32가 일치해야 하며, 겹치는 항목, 64 MiB를 넘은 뒤 1000:1을 초과하는 압축률, 64 GiB를 넘는 출력은 추출을 중단시킵니다. Chromium 기반 브라우저에서는 파일이 선택한 폴더로 바로 들어가며 기존 파일은 유지되고, 다른 브라우저에서는 선택 항목이 ZIP 하나로 다운로드됩니다.

    아카이브를 만들 때는 각 파일을 압축기를 거쳐 저장할 파일로 스트리밍하며, UTF-8 이름, 4 GiB 이상 파일용 ZIP64, 긴 TAR 이름용 pax 헤더를 사용합니다.

    실용적인 예제

    다운로드한 파일 들여다보기: 2 GB release.zip을 열면 압축을 풀지 않고도 1초 만에 40,000개 파일과 크기를 볼 수 있습니다.

    백업에서 로그 하나 꺼내기: logs.tar.gz를 “2026-10”으로 필터링하고 일치하는 파일을 선택해 그 파일만 폴더로 추출합니다.

    의심스러운 아카이브 확인: 항목에 “../../etc/passwd”가 들어 있는 ZIP은 해당 항목이 안전하지 않음으로 표시된 채 목록에 나타나며, 절대 기록되지 않습니다.

    프로젝트 폴더 압축: 폴더를 추가하고 TAR.ZST 수준 3을 선택하면 폴더 구조를 유지한 압축 아카이브가 저장됩니다.

    이 도구 사용 방법

    1. 1

      아카이브 열기

      ZIP, TAR, TAR.GZ, TAR.ZST, TAR.BR, GZ, ZST 또는 BR 파일을 끌어다 놓거나 선택합니다. 읽기가 끝나면 항목 목록이 나타납니다.

    2. 2

      파일 찾기와 선택

      “필터”에 이름의 일부를 입력한 뒤 행을 클릭하거나 “일치 항목 선택”을 사용합니다. 폴더를 선택하면 안의 모든 항목이 선택됩니다.

    3. 3

      추출

      Chromium 기반 브라우저에서는 “폴더에 추출…”, 어디서나 “ZIP으로 다운로드”, 파일 하나를 선택했다면 “파일 저장”을 고릅니다.

    4. 4

      아카이브 만들기

      “아카이브 만들기”에서 파일이나 폴더를 추가하고 형식과 수준을 고른 뒤 새 아카이브를 저장합니다.

    팁 및 모범 사례

    • TAR이 들어 있지 않은 단일 .gz, .zst, .br 파일은 항목 하나로 표시되며, 크기는 추출한 뒤에만 알 수 있습니다.
    • 암호화된 ZIP 항목과 BZIP2, LZMA, Deflate64 같은 방식은 목록에는 표시되지만 추출되지 않습니다.
    • 취소하면 워커가 즉시 멈추고, 일부만 기록된 파일은 버려집니다.
    • gzip, Brotli, Zstandard가 내 데이터를 어떻게 압축하는지 비교하려면 “압축 벤치마크”를 사용해 보세요.

    인코딩

    • B64Base64 인코더 / 디코더텍스트나 파일을 Base64로 인코딩하고 다시 디코딩합니다. 표준·URL 안전 알파벳, 패딩, 76자 줄 바꿈, 이미지 미리보기 지원. 브라우저에서 처리.
    • B32Base32 인코더 / 디코더RFC 4648, Crockford, z-base-32 알파벳으로 Base32를 인코딩·디코딩합니다. 패딩과 대소문자 옵션 지원, 텍스트와 파일 모두 브라우저에서 처리.
    • B58Base58 인코더 / 디코더Bitcoin, Flickr, Ripple 알파벳으로 Base58을 인코딩·디코딩합니다. 텍스트와 1 MiB 이하 파일 지원, 브라우저에서 로컬로 처리하며 업로드하지 않습니다.
    • 0xHex 인코더 / 디코더텍스트나 파일을 16진수로 변환하고 되돌립니다. 문자셋과 대소문자 선택 가능, 공백·콜론·하이픈·0x 접두사가 있는 hex도 디코딩. 브라우저에서 처리.
