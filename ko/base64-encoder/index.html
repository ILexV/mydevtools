Base64 인코더 / 디코더

텍스트나 파일을 Base64로 인코딩하고 다시 디코딩합니다. 표준·URL 안전 알파벳, 패딩, 76자 줄 바꿈, 이미지 미리보기 지원. 브라우저에서 처리.

입력 내용과 파일은 브라우저 밖으로 전송되지 않습니다

인코딩할 텍스트를 입력하거나 디코딩할 Base64 데이터를 붙여넣으세요. 아래에 파일을 끌어다 놓을 수도 있습니다.

아무것도 업로드하지 않고 텍스트나 모든 파일을 Base64로 변환하고 되돌릴 수 있습니다. Rust로 컴파일한 WebAssembly 모듈이 브라우저에서 처리하며, 디코딩한 이미지는 미리보기로 보여 주고 바이너리 데이터는 알맞은 확장자로 다운로드할 수 있습니다.

상세 기능

텍스트는 먼저 선택한 문자셋(UTF-8, UTF-16LE, UTF-16BE, ASCII, ISO-8859-1)으로 바이트로 바뀐 뒤, RFC 4648 표준 알파벳(+, /) 또는 JWT와 URL 파라미터에서 쓰는 URL 안전 알파벳(-, _)으로 인코딩됩니다. = 패딩은 필수, 선택, 없음 중에서 고를 수 있고, MIME 이메일처럼 76자마다 줄을 바꿀 수도 있습니다.

디코딩할 때는 결과 바이트를 검사합니다. 읽을 수 있는 텍스트는 출력 칸에 표시하고, PNG, JPEG, GIF, WebP, BMP, ICO, TIFF, SVG 이미지는 픽셀 크기와 함께 미리보기로 보여 주며, PDF, ZIP, GZIP, MP3, MP4와 실행 파일은 시그니처로 식별합니다. 텍스트가 아닌 데이터는 다운로드로 decoded.png처럼 알맞은 확장자를 붙여 저장합니다.

파일은 선택하거나 페이지에 끌어다 놓을 수 있으며, 파일이 선택된 동안에는 텍스트 칸이 무시됩니다. 파일은 Web Worker에서 1 MiB 단위로 읽고 진행률 표시줄과 취소 버튼을 제공하지만, 파일 전체를 메모리에 올리므로 실제 한도는 기기의 RAM입니다. 아주 긴 결과는 출력 칸에 미리보기만 표시되고 전체는 다운로드로 저장합니다.

실용적인 예제

텍스트를 Base64로: Hello, World!는 SGVsbG8sIFdvcmxkIQ==가 되고, UTF-8에서 Привет는 0J/RgNC40LLQtdGC가 됩니다(입력 12바이트, 출력 16자).

URL 안전·패딩 없음: <<???>>는 표준 알파벳으로 PDw/Pz8+Pg==, URL 안전 (-_)과 패딩 없음으로는 PDw_Pz8-Pg가 되며, 이는 JWT 세그먼트 형식과 같습니다.

패딩 없는 입력: 기본값 필수 패딩에서는 SGk 디코딩이 실패합니다. 패딩을 선택 사항으로 바꾸면 Hi가 나옵니다.

Base64를 이미지로: PNG의 Base64(iVBORw0KGgo로 시작)를 붙여 넣으면 1×1 px 같은 크기와 함께 이미지가 표시되고, 다운로드하면 decoded.png로 저장됩니다.

이 도구 사용 방법

  1. 1

    텍스트 입력 또는 파일 선택

    입력 (텍스트)에 텍스트를 입력하거나 붙여 넣고, 또는 파일을 페이지에 끌어다 놓거나 파일 선택을 클릭합니다. 선택한 파일이 텍스트보다 우선합니다.

  2. 2

    옵션 설정

    텍스트 문자셋(대개 UTF-8), 알파벳(표준 (+/) 또는 URL 안전 (-_)), 패딩을 고르고, MIME 이메일용이라면 줄 바꿈을 76자로 설정합니다.

  3. 3

    인코딩 또는 디코딩

    인코딩을 누르면 Base64가, 디코딩을 누르면 텍스트, 이미지 미리보기 또는 바이너리 파일이 나옵니다. 오류가 나면 잘못된 문자나 패딩 오류처럼 원인을 알려 줍니다.

  4. 4

    결과 복사 또는 다운로드

    복사는 출력을 클립보드에 넣고 다운로드는 파일로 저장합니다. 교체는 출력을 입력 칸으로 옮겨 왕복 변환을 확인할 수 있게 합니다.

팁 및 모범 사례

  • Base64는 데이터를 약 33% 늘립니다(3바이트가 4자로). 암호화가 아니라 인코딩이므로 누구나 디코딩할 수 있습니다.
  • data URI는 디코딩 전에 data:image/png;base64, 접두사를 지우세요. 디코더는 Base64 부분만 받습니다.
  • JWT 헤더와 페이로드는 패딩 없는 URL 안전 알파벳을 씁니다. URL 안전 (-_)과 선택 사항 패딩을 고르면 eyJhbGciOiJIUzI1NiJ9가 {"alg":"HS256"}로 디코딩됩니다.
  • 이메일이나 PEM 파일의 줄 바꿈된 Base64를 디코딩하려면 공백/개행 허용을 켜 두고, 한 줄짜리 깨끗한 입력인지 확인하려면 끄세요.
  • 문자셋이 중요합니다. é는 UTF-8에서 w6k=, ISO-8859-1에서 6Q==이므로 인코딩할 때와 같은 문자셋으로 디코딩하세요.
  • 한 번 연 페이지는 네트워크 없이도 동작합니다.

인코딩

  • B32Base32 인코더 / 디코더RFC 4648, Crockford, z-base-32 알파벳으로 Base32를 인코딩·디코딩합니다. 패딩과 대소문자 옵션 지원, 텍스트와 파일 모두 브라우저에서 처리.
  • B58Base58 인코더 / 디코더Bitcoin, Flickr, Ripple 알파벳으로 Base58을 인코딩·디코딩합니다. 텍스트와 1 MiB 이하 파일 지원, 브라우저에서 로컬로 처리하며 업로드하지 않습니다.
  • 0xHex 인코더 / 디코더텍스트나 파일을 16진수로 변환하고 되돌립니다. 문자셋과 대소문자 선택 가능, 공백·콜론·하이픈·0x 접두사가 있는 hex도 디코딩. 브라우저에서 처리.
  • %20URL 인코더 / 디코더URL과 쿼리 문자열을 컴포넌트, URI, 폼 모드로 퍼센트 인코딩·디코딩합니다. UTF-8, UTF-16, Latin-1 문자셋 지원, 브라우저에서 로컬로 처리.
