DNS 조회

이 컴퓨터의 DNS 리졸버로 A, AAAA, CNAME, MX, NS, TXT, SOA, PTR 레코드를 조회합니다.

조회는 로컬 에이전트를 통해 이 컴퓨터의 DNS 리졸버로 갑니다. 이름과 응답은 이 페이지에 남습니다.

세션이 만료되거나 에이전트가 다시 시작될 때까지 이 브라우저에 연결이 저장됩니다. 연결 해제하면 삭제됩니다.

에이전트 준비

로컬 에이전트를 받아 실행한 뒤 이 페이지로 돌아옵니다.

에이전트 안내와 다운로드
  1. MyDevTools Agent를 실행합니다. 이 컴퓨터에 이미 설정된 DNS 리졸버를 사용합니다.
  2. 에이전트 창에서 페어링 코드를 복사합니다.
  3. 아래에 코드를 붙여 넣습니다. 브라우저가 로컬 네트워크 접근을 물으면 이 연결에 대해 허용합니다.

브라우저는 이름과 레코드 종류를 127.0.0.1의 에이전트에만 보냅니다. 에이전트는 이 컴퓨터의 DNS 리졸버에 묻습니다. 질의는 MyDevTools 서버로 가지 않고, 공개 DNS-over-HTTPS도 쓰지 않습니다. 이 브라우저는 고른 레코드 종류만 기억하고 이름, 응답, 페어링 코드는 저장하지 않습니다.

이름
호스트 이름입니다. 종류가 PTR이면 IP 주소입니다. 국제화 이름은 punycode(xn--)로 넣습니다. 에이전트는 이 컴퓨터의 리졸버에 묻고, 공개 DoH에는 묻지 않습니다.
종류
레코드 종류는 하나입니다. PTR은 IP 주소를 뒤집습니다. 이 컴퓨터의 검색 목록은 그대로 적용됩니다.

DNS 조회는 이 컴퓨터에 설정된 리졸버에 이름 하나와 레코드 종류 하나를 묻습니다. 브라우저가 직접 질의를 보내지 않습니다. 로컬 에이전트는 dns.lookup을 http.request, icmp.trace와 따로 부여합니다.

상세 기능

지원 종류는 A, AAAA, CNAME, MX, NS, TXT, SOA, PTR입니다. IP 주소는 PTR에서만 받으며, 에이전트가 in-addr.arpa 또는 ip6.arpa로 뒤집습니다. 응답 구역은 도착한 그대로 보이며, 주소와 함께 온 CNAME도 남습니다. 빈 NOERROR는 레코드 없음이고, NXDOMAIN은 그 이름이 DNS에 없다는 뜻입니다. 질의는 운영체제 리졸버로 가므로 분할 DNS와 이 컴퓨터의 검색 목록이 유지됩니다. MyDevTools 서버로 가지 않고, 공개 DNS-over-HTTPS도 아닙니다. 고른 레코드 종류는 이 브라우저에 남고, 이름과 레코드는 남지 않습니다.

실용적인 예제

  • 종류 A의 example.com은 이 컴퓨터 리졸버가 준 IPv4 주소를 보여 줍니다.
  • 종류 MX의 example.com은 메일 서버와 우선순위를 보여 줍니다.
  • 종류 PTR의 1.1.1.1은 역방향 이름을 묻습니다.

이 도구 사용 방법

  1. 1

    로컬 에이전트 실행

    에이전트를 받아 실행하고 페어링 코드를 복사합니다.

  2. 2

    DNS 조회 페어링

    코드를 붙여 연결합니다. 페이지는 dns.lookup을 요청하고, 이 브라우저가 이미 가진 권한은 유지합니다.

  3. 3

    이름 하나 조회

    호스트 이름을 넣고 A, AAAA, CNAME, MX, NS, TXT, SOA, PTR 중 하나를 고른 뒤 조회를 누릅니다. PTR이면 IP 주소를 넣습니다.

  4. 4

    응답 읽기

    표에는 이름, 종류, TTL, MX 우선순위, 데이터가 나옵니다. 응답은 텍스트로 복사할 수 있습니다. 페이지를 다시 열면 지워집니다.

팁 및 모범 사례

  • 잃거나 거부된 조회는 오류입니다. 빈 NOERROR 응답은 실패가 아닙니다.
  • hosts 파일은 보지 않습니다. DNS 리졸버만 응답합니다.
  • 동시에 최대 네 건입니다. 네트워크 스캔도, 종류 나열도 아닙니다.
  • 공개된 Windows 다운로드는 이 페이지보다 오래되었을 수 있습니다. DNS 조회에는 dns.lookup을 알리는 에이전트가 필요합니다.
