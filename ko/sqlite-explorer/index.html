SQLite Explorer

로컬 SQLite 데이터베이스를 브라우저에서 열어 테이블, 뷰, 인덱스를 살펴보고 SQL을 실행하고 결과를 내보낼 수 있습니다. 파일은 업로드되지 않습니다.

입력 내용과 파일은 브라우저 밖으로 전송되지 않습니다

데이터베이스

SQLite 파일을 여기에 끌어다 놓으세요

.sqlite, .sqlite3, .db, .db3 또는 .s3db, 최대 512 MiB.

기본값은 꺼짐이며 사본은 읽기 전용입니다. 켜면 INSERT, UPDATE 및 스키마 변경이 브라우저 메모리의 사본에 적용됩니다. 원본 파일은 절대 수정되지 않으며, 변경된 사본을 다운로드할 수 있습니다.

스키마

데이터베이스에 테이블, 뷰, 인덱스, 트리거가 없습니다.

    파일은 이 기기에 그대로 남습니다. SQLite는 전용 Web Worker에서 WebAssembly로 실행되며, 아무것도 업로드되지 않고 SQL 텍스트나 데이터도 저장되지 않습니다.

    SQL

    Ctrl 또는 Cmd + Enter를 눌러 실행합니다. 세미콜론으로 구분한 여러 문은 순서대로 실행되며, 행을 반환하는 마지막 문의 결과가 표시됩니다.

    쿼리 결과는 임시 테이블에 보관되고 페이지 단위로 읽힙니다.
    결과

    데이터베이스를 열고 테이블을 선택하거나 SQL을 실행하면 여기에 행이 표시됩니다.

    결과 내보내기

    현재 테이블 또는 쿼리의 모든 행을 내보냅니다. NULL은 CSV에서 빈 값, JSON에서 null이 되며 BLOB 값은 hex로 기록됩니다.

    변경된 사본

    변경 사항이 반영된 메모리 사본을 새 SQLite 파일로 다운로드합니다. 페이지를 닫거나 작업을 취소하거나 다른 파일을 열면 변경 사항이 사라집니다.

    SQLite Explorer는 로컬 SQLite 데이터베이스를 브라우저에서 바로 엽니다. 테이블, 뷰, 인덱스, 트리거를 확인하고 열과 CREATE 문을 살펴보며 행을 페이지별로 넘겨 보고 원하는 SQL을 실행하세요. .db 파일은 절대 업로드되지 않습니다.

    상세 기능

    WebAssembly로 컴파일된 공식 SQLite 빌드가 전용 Web Worker에서 실행되며 이 페이지에서만 로드됩니다. 선택한 파일은 worker 메모리로 복사됩니다. 기본적으로 사본은 읽기 전용이므로 데이터를 변경하는 문은 거부되고 디스크의 원본 파일은 전혀 건드리지 않습니다.

    “메모리 사본 변경 허용”을 켜면 사본에 INSERT, UPDATE, DELETE 또는 스키마 변경을 실행한 뒤 새 데이터베이스 파일로 다운로드할 수 있습니다. 원본에는 아무것도 다시 쓰지 않습니다.

    여러 문으로 된 스크립트는 순서대로 실행됩니다. 행을 반환하는 마지막 문이 결과가 됩니다. SELECT, WITH 또는 VALUES 쿼리는 임시 테이블(최대 1,000,000행)에 저장되고 가상화된 표가 이를 페이지 단위로 읽습니다. PRAGMA, EXPLAIN, RETURNING 출력은 최대 10,000행까지 수집됩니다. 테이블을 탐색할 때는 LIMIT와 OFFSET으로 직접 읽습니다. 결과는 청크 단위로 CSV, JSON, JSONL 또는 SQL INSERT 문으로 내보냅니다.

    실용적인 예제

    테이블 보기: 스키마 목록에서 테이블을 클릭하면 열, 인덱스, 외래 키, 행이 표시됩니다.

    행 개수 세기: “행 개수” 예제는 모든 테이블에 대한 UNION ALL 쿼리를 만듭니다.

    파일 검사: PRAGMA integrity_check;를 실행해 휴대폰이나 앱에서 복사한 데이터베이스를 검증합니다.

    사본에서 데이터 수정: 변경을 허용하고 UPDATE settings SET value = 'on' WHERE key = 'debug';를 실행한 다음 변경된 데이터베이스를 다운로드합니다.

    이 도구 사용 방법

    1. 1

      데이터베이스 열기

      .sqlite, .db 또는 .sqlite3 파일을 끌어다 놓거나 선택합니다. 스키마 목록과 파일 정보가 나타납니다.

    2. 2

      객체 탐색

      테이블이나 뷰를 클릭하면 행과 구조를, 인덱스나 트리거를 클릭하면 정의를 볼 수 있습니다.

    3. 3

      SQL 실행

      예제를 고르거나 직접 쿼리를 작성하고 Ctrl 또는 Cmd + Enter를 누릅니다.

    4. 4

      내보내기 또는 저장

      현재 결과를 CSV, JSON, JSONL 또는 INSERT 문으로 내보냅니다. 쓰기 가능 모드에서는 변경된 데이터베이스를 다운로드합니다.

    팁 및 모범 사례

    • 쓰기 가능 모드에서도 원본 파일은 절대 수정되지 않습니다. 변경 사항은 다운로드하기 전까지 메모리 사본에만 존재합니다.
    • 데이터베이스를 사용하는 앱이 WAL 모드라면 먼저 앱을 닫거나 checkpoint를 실행해 -wal 내용이 기본 파일에 반영되게 하세요. 기본 파일만 읽습니다.
    • 암호화된 데이터베이스(SQLCipher 등)는 열 수 없습니다.
    • 식별자는 큰따옴표로 감싸세요: SELECT * FROM "order items".
    • 취소를 누르면 worker가 즉시 중지되고 파일을 다시 열며, 저장하지 않은 변경 사항은 삭제됩니다.
    • 큰 64비트 정수도 정확하게 유지됩니다. JavaScript 숫자로는 반올림될 경우 텍스트로 표시되고 내보내집니다.

    구조화된 데이터

    • {}JSON 포맷터브라우저에서 JSON을 포맷·압축·검증합니다. 2/4칸 공백 또는 탭 들여쓰기, 재귀적 키 정렬, 큰 숫자 원형 유지, .json 파일 열기와 저장 지원.
    • TSJSON → TypeScript 변환기JSON 샘플에서 TypeScript 인터페이스나 타입 별칭을 생성합니다. 중첩 타입, 배열 항목 병합, 선택적 필드, export 키워드 지원. 브라우저에서 실행.
    • J{}대용량 JSON / JSONL 탐색기대용량 JSON과 JSONL을 로컬에서 열고 색인, 검색, 내보내기하세요. 가상 표, 지연 트리, 정확한 숫자를 제공합니다.
    • CSV대용량 CSV/TSV 탐색기매우 큰 CSV 또는 TSV 파일을 로컬에서 열고 필터링, 정렬, 그룹화하고 살펴보고 내보냅니다. 열 유형을 지정하고 CSV, JSONL 또는 Parquet으로 내보낼 수 있습니다.
