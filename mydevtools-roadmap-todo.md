# MyDevTools — TODO / Roadmap

> **Концепция:** сложная обработка данных, простой интерфейс, всё локально в браузере. Сайт статический (GitHub Pages + Cloudflare), без backend. Rust/WebAssembly используется там, где он даёт преимущество при обработке больших объёмов данных, потоковых вычислениях или переиспользовании зрелых библиотек. Простые операции могут оставаться на JavaScript / Web APIs.

## Принципы и общие требования

- [x] Все файлы и чувствительные данные обрабатываются локально, без отправки на сервер.
- [x] Для каждого инструмента есть простой самостоятельный интерфейс: выбор файла/ввод → настройки → результат/экспорт (без обязательных визуальных pipeline).
- [x] Разграничить задачи JavaScript/Web APIs и Rust/WASM; не переносить простые операции в WASM без причины.
- [x] Предусмотреть поддержку больших файлов без обязательной полной загрузки в память.
- [x] Тяжёлые вычисления выполнять вне UI-потока (Web Workers).
- [ ] Отображать прогресс, количество обработанных байтов, прошедшее время, скорость и состояние задачи.
- [ ] Поддержать отмену длительных операций и корректное освобождение ресурсов.
- [x] WASM-модули загружать по требованию; не включать все библиотеки в стартовый bundle.
- [ ] Обработать ограничения памяти браузера, квоты хранилища и нехватку ресурсов понятными сообщениями.
- [x] Проверить работу при отключённом интернете после загрузки нужных модулей (PWA/offline caching).
- [x] Не сохранять секреты/ключи/содержимое файлов в localStorage по умолчанию.
- [ ] Добавить тесты корректности и производительности на файлах разных размеров.

## Этап 0 — Общее ядро обработки данных (приоритет P0)

- [ ] Реализовать чтение `File` / `Blob` порциями (chunked reading) с настраиваемым размером блока.
- [x] Организовать передачу блоков в Web Worker с минимизацией копирования (Transferable buffers, где уместно).
- [x] Реализовать мост JS ↔ Rust/WASM и переиспользуемую систему загрузки отдельных WASM-модулей.
- [x] Реализовать потоковую обработку с backpressure, чтобы очередь блоков не росла бесконтрольно.
- [x] Добавить сбор прогресса: байты, %, elapsed, MB/s, приблизительное оставшееся время (если применимо).
- [ ] Реализовать отмену и очистку буферов, worker и WASM-памяти.
- [ ] Унифицировать ошибки: неверный формат, повреждённый файл, нехватка памяти, отмена пользователем.
- [x] Скачивание результата через Blob (hash, JSON/CSV, AEAD, PDF, изображения).
- [ ] File System Access API (`showSaveFilePicker`) для больших результатов, с fallback на Blob в браузерах без поддержки. Сейчас все скачивания идут через Blob.
- [ ] Добавить тестовые fixtures: пустой файл, 1 КБ, 100 МБ, 1 ГБ+, бинарные и некорректные данные.
- [ ] Замерить throughput, память и отзывчивость UI в основных браузерах.

**Готово, когда:** два разных инструмента могут использовать одно ядро; большой файл обрабатывается порциями, прогресс и отмена работают, UI остаётся отзывчивым.

**Прогресс 2026-10-08:** для PDF, QR и файлового AEAD исправлены завершение pending-задач при отмене/падении worker, очистка ресурсов и повторный запуск. Ошибки запуска/исполнения worker локализованы на 10 языков и не маскируются под неверный формат файла. Для QR проверены остановка MediaStream и закрытие ImageBitmap. Общие пункты выше остаются открытыми: это не полная унификация всех инструментов и не реализация File System Access API.

## Этап 1 — High Performance File Tools (P0–P1)

### 1.1 File Hash Calculator (P0)

- [x] Выбор одного или нескольких локальных файлов (включая большие файлы).
- [x] Поддержать MD5, SHA-1, SHA-256, SHA-512, BLAKE3, xxHash64.
- [x] Реализовать потоковое вычисление без полной загрузки файла в память.
- [x] Вычислять несколько выбранных хэшей за один проход по файлу.
- [x] Отображать прогресс, скорость (MB/s), время вычисления и размер файла.
- [x] Добавить копирование хэшей и экспорт результатов (TXT/CSV/JSON).
- [x] Поддержать проверку файла по введённой контрольной сумме (case-insensitive hex; понятное сравнение).
- [x] Различать криптографические и некриптографические алгоритмы (xxHash64 не для проверки подлинности).
- [x] Проверить результаты по известным тестовым векторам и внешним эталонам.
- [x] Сравнить скорость Rust/WASM с Web Crypto на типовых файлах; зафиксировать результаты, не предполагать, что WASM всегда быстрее.

Проверено: файл 2 ГиБ + 17 байт с шестью алгоритмами; пакетная очередь, отмена и повторный запуск; интерфейс и SEO на всех 10 языках. Замеры SHA-256 (10/100/1024 МиБ, Chromium/Firefox), методика и ограничения памяти — в [QA-отчёте](docs/inventory/parity-fixtures.md#5-hash-calculator-and-worker-lifecycle-2026-10-08). Общие пункты про универсальный Task API, остальные worker-домены, Edge/Safari и 5 ГиБ этим не закрываются.

**Готово, когда:** многогигабайтный файл хэшируется потоково без зависания UI; несколько алгоритмов получают корректный результат за один проход.

### 1.2 Binary File Analyzer / Hex Viewer (P1)

- [x] Просмотр крупных файлов в hex + ASCII/UTF-8, виртуализация отображаемых строк.
- [x] Переход к смещению, поиск сигнатур и последовательностей байтов.
- [x] Определение вероятного формата по magic bytes.
- [x] Отображение размера, смещений, заголовков и базовой энтропии по блокам.
- [x] Экспорт выбранного диапазона без копирования всего файла в память.

Реализован `hex-viewer` на всех 10 языках (2026-10-14): локальный файл, виртуальные строки по 16 байт (hex, ASCII и UTF-8), переход по десятичному или `0x` смещению, сигнатура по тем же magic bytes, что и у base64, поиск текста или hex и энтропия Шеннона по блокам 4 КиБ. Поиск и энтропия идут в worker с прогрессом и отменой; видимые строки читаются через `File.slice`. Экспорт — включительный диапазон как срез Blob, без второй копии всего файла. Пределы: образец 256 байт, 200 совпадений, чтение поиска по 1 МиБ, энтропия целиком до 1 МиБ и далее не больше 256 проб, экспорт 256 МиБ. Правка байтов и дизассемблирование не входят. В браузере на разреженном файле 2 ГиБ проверены переход к последнему байту, останов поиска `00` на 200 совпадениях и 256 проб энтропии. Полный проход по плотному многогигабайтному файлу без раннего совпадения не засекался.

## Этап 2 — Data Engineering Tools (P0–P2)

### 2.1 Large JSON / JSONL Explorer (P0)

- [x] Открытие крупных JSON и JSONL с понятным отображением структуры.
- [x] Поиск по ключам/значениям и просмотр дерева с ленивым раскрытием узлов.
- [x] Фильтрация и выборочное извлечение полей/записей.
- [x] Диагностика ошибок формата с позицией, если доступна.
- [x] Для JSONL — потоковая обработка построчно; для обычного JSON — отдельно оценить ограничения парсера.
- [x] Экспорт выбранных данных в JSONL/CSV.

Реализован `json-explorer` на всех 10 языках. JSONL читается блоками по 1 MiB; проверены 2 000 001 строка и отдельный файл >5 GiB. Обычный JSON ограничен явно выбранными 8/16/32/64 MiB, запись JSONL — 1–8 MiB, глубина — до 256, экспорт — до 256 MiB. Числа сохраняют исходное написание без потери точности; таблица виртуализирована, дерево раскрывается порциями.

### 2.2 Large CSV Explorer (P0)

- [x] Потоковый импорт CSV/TSV, определение разделителя и кодировки.
- [x] Виртуализированный табличный просмотр миллионов строк.
- [ ] Фильтрация, сортировка, группировка и простые агрегаты.
- [ ] Выбор колонок, преобразование типов, предпросмотр результатов.
- [ ] Экспорт в CSV/JSONL/Parquet, когда доступен подходящий движок.
- [x] Отображение ограничений: не все сортировки/группировки возможны без дополнительной памяти или временного хранилища.

Реализован `csv-explorer` на всех 10 языках: фильтры, точные числовые сравнения, выбор колонок, полный экспорт отфильтрованных данных в CSV/JSONL. Проверены 2 000 001 строка и отдельный файл >5 GiB. Кодировки: UTF-8, UTF-16 с BOM и явно выбранные legacy-варианты. **Смешанные пункты выше намеренно не закрыты:** сортировка, группировка/агрегаты, преобразование типов и Parquet пока отсутствуют. Пределы: поле 2 MiB, запись 8 MiB, 512 колонок, 100 млн записей, экспорт 512 MiB.

### 2.3 Parquet Viewer (P0–P1)

- [x] Открытие локального Parquet, просмотр схемы и метаданных.
- [x] Табличный просмотр колонок с виртуализацией.
- [x] Выборочные запросы к колонкам и статистика row groups.
- [ ] Фильтры и агрегаты.
- [x] Экспорт выбранных колонок в CSV/JSONL.
- [x] Тесты на типы колонок и сжатия uncompressed, Snappy, gzip и Brotli.
- [ ] Проверка на крупных файлах.

Реализован `parquet-explorer` на всех 10 языках (2026-10-14): локальный `.parquet`, схема, метаданные, статистика row groups, виртуализированный просмотр выбранных колонок и экспорт этих колонок в CSV/JSONL. Тесты покрывают STRING, INT64 с сохранением десятичного написания (включая значения больше 2^53), BOOLEAN, DOUBLE, TIMESTAMP и BYTE_ARRAY. В браузере также зарегистрированы Zstd, LZ4 и LZ4_RAW; LZO не поддерживается. Пределы: 512 колонок, ячейка 1 MiB, экспорт 512 MiB. SQL, фильтры, агрегаты, сортировка и запись Parquet в этот срез не входят. Крупные файлы этим срезом не проверялись.

## UX и продуктовые задачи (сквозные)

- [x] Каждый инструмент — отдельная понятная страница с одной основной задачей.
- [x] Стандартный шаблон: drag-and-drop/выбор файла → параметры → прогресс → результат.
- [x] Возможность запускать обработку нескольких файлов и видеть ошибки по каждому.

- [ ] При использовании WASM показывать статус загрузки модуля отдельно от обработки файла.

- [ ] Объяснять браузерные ограничения (CORS, память, доступ к файловой системе, многопоточность).
- [x] Добавить на страницы тяжёлых инструментов примеры входных данных и типовых сценариев.
- [x] Проверить доступность клавиатурой и работу на мобильных устройствах (с ограничениями по объёму файлов).
