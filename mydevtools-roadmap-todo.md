# MyDevTools — TODO / Roadmap

> **Концепция:** сложная обработка данных, простой интерфейс, всё локально в браузере. Сайт статический (GitHub Pages + Cloudflare), без backend. Rust/WebAssembly используется там, где он даёт преимущество при обработке больших объёмов данных, потоковых вычислениях или переиспользовании зрелых библиотек. Простые операции могут оставаться на JavaScript / Web APIs.

## Принципы и общие требования

- [x] Все файлы и чувствительные данные обрабатываются локально, без отправки на сервер.
- [x] Для каждого инструмента есть простой самостоятельный интерфейс: выбор файла/ввод → настройки → результат/экспорт (без обязательных визуальных pipeline).
- [x] Разграничить задачи JavaScript/Web APIs и Rust/WASM; не переносить простые операции в WASM без причины.
- [x] Предусмотреть поддержку больших файлов без обязательной полной загрузки в память.
- [x] Тяжёлые вычисления выполнять вне UI-потока (Web Workers).
- [ ] Отображать прогресс, количество обработанных байтов, прошедшее время, скорость и состояние задачи.
- [ ] Поддержать отмену длительных операций и корректное освобождение ресурсов.
- [x] WASM-модули загружать по требованию; не включать все библиотеки в стартовый bundle.
- [ ] Обработать ограничения памяти браузера, квоты хранилища и нехватку ресурсов понятными сообщениями.
- [x] Проверить работу при отключённом интернете после загрузки нужных модулей (PWA/offline caching).
- [x] Не сохранять секреты/ключи/содержимое файлов в localStorage по умолчанию.
- [ ] Добавить тесты корректности и производительности на файлах разных размеров.

## Этап 0 — Общее ядро обработки данных (приоритет P0)

- [ ] Спроектировать универсальный интерфейс `Task`: `start`, `progress`, `cancel`, `result`, `error`.
- [ ] Реализовать чтение `File` / `Blob` порциями (chunked reading) с настраиваемым размером блока.
- [x] Организовать передачу блоков в Web Worker с минимизацией копирования (Transferable buffers, где уместно).
- [x] Реализовать мост JS ↔ Rust/WASM и переиспользуемую систему загрузки отдельных WASM-модулей.
- [x] Реализовать потоковую обработку с backpressure, чтобы очередь блоков не росла бесконтрольно.
- [x] Добавить сбор прогресса: байты, %, elapsed, MB/s, приблизительное оставшееся время (если применимо).
- [ ] Реализовать отмену и очистку буферов, worker и WASM-памяти.
- [ ] Унифицировать ошибки: неверный формат, повреждённый файл, нехватка памяти, отмена пользователем.
- [ ] Реализовать скачивание результата через Blob / File System Access API (с fallback для браузеров без поддержки).
- [ ] Добавить тестовые fixtures: пустой файл, 1 КБ, 100 МБ, 1 ГБ+, бинарные и некорректные данные.
- [ ] Замерить throughput, память и отзывчивость UI в основных браузерах.

**Готово, когда:** два разных инструмента могут использовать одно ядро; большой файл обрабатывается порциями, прогресс и отмена работают, UI остаётся отзывчивым.

## Этап 1 — High Performance File Tools (P0–P1)

### 1.1 File Hash Calculator (P0)

- [ ] Выбор одного или нескольких локальных файлов (включая большие файлы).
- [x] Поддержать MD5, SHA-1, SHA-256, SHA-512, BLAKE3, xxHash64.
- [x] Реализовать потоковое вычисление без полной загрузки файла в память.
- [x] Вычислять несколько выбранных хэшей за один проход по файлу.
- [ ] Отображать прогресс, скорость (MB/s), время вычисления и размер файла.
- [ ] Добавить копирование хэшей и экспорт результатов (TXT/CSV/JSON).
- [x] Поддержать проверку файла по введённой контрольной сумме (case-insensitive hex; понятное сравнение).
- [x] Различать криптографические и некриптографические алгоритмы (xxHash64 не для проверки подлинности).
- [x] Проверить результаты по известным тестовым векторам и внешним эталонам.
- [ ] Сравнить скорость Rust/WASM с Web Crypto на типовых файлах; зафиксировать результаты, не предполагать, что WASM всегда быстрее.

**Готово, когда:** многогигабайтный файл хэшируется потоково без зависания UI; несколько алгоритмов получают корректный результат за один проход.

### 1.2 Binary File Analyzer / Hex Viewer (P1)

- [ ] Просмотр крупных файлов в hex + ASCII/UTF-8, виртуализация отображаемых строк.
- [ ] Переход к смещению, поиск сигнатур и последовательностей байтов.
- [ ] Определение вероятного формата по magic bytes.
- [ ] Отображение размера, смещений, заголовков и базовой энтропии по блокам.
- [ ] Экспорт выбранного диапазона без копирования всего файла в память.

### 1.3 Large File Diff (P1)

- [ ] Сравнение больших текстовых файлов с ограниченным потреблением памяти.
- [ ] Сравнение бинарных файлов по блокам, список отличающихся диапазонов.
- [ ] Настройки для текстового сравнения: переводы строк, пробелы, кодировка.
- [ ] Экспорт отчёта о различиях.

### 1.4 Compression Tools / Benchmark (P1)

- [ ] Сжатие и распаковка ZIP, TAR/GZIP, а также сравнение Zstd/Brotli/Gzip там, где это реализуемо в браузере.
- [ ] Настройка уровня сжатия и отображение коэффициента сжатия.
- [ ] Измерение времени, скорости и потребления памяти.
- [ ] Просмотр содержимого архива, извлечение выбранных файлов.
- [ ] Защита от path traversal и небезопасных имён файлов при извлечении.
- [ ] Ограничения против архивных бомб и чрезмерного расхода памяти.

### 1.5 Image & PDF Tools (P2, расширение существующих)

- [ ] Пакетная обработка изображений с отчётом о скорости/экономии размера.
- [x] Конвертация, изменение размера и оптимизация изображений без сервера.
- [ ] PDF: разделение, объединение, удаление, поворот и перестановка страниц.
- [x] Удаление метаданных там, где это корректно поддерживается.
- [ ] По возможности обрабатывать файлы по частям; документировать случаи, где библиотеке нужен целый файл.

## Этап 2 — Data Engineering Tools (P0–P2)

### 2.1 Large JSON / JSONL Explorer (P0)

- [ ] Открытие крупных JSON и JSONL с понятным отображением структуры.
- [ ] Поиск по ключам/значениям и просмотр дерева с ленивым раскрытием узлов.
- [ ] Фильтрация и выборочное извлечение полей/записей.
- [ ] Диагностика ошибок формата с позицией, если доступна.
- [ ] Для JSONL — потоковая обработка построчно; для обычного JSON — отдельно оценить ограничения парсера.
- [ ] Экспорт выбранных данных в JSONL/CSV.

### 2.2 Large CSV Explorer (P0)

- [ ] Потоковый импорт CSV/TSV, определение разделителя и кодировки.
- [ ] Виртуализированный табличный просмотр миллионов строк.
- [ ] Фильтрация, сортировка, группировка и простые агрегаты.
- [ ] Выбор колонок, преобразование типов, предпросмотр результатов.
- [ ] Экспорт в CSV/JSONL/Parquet, когда доступен подходящий движок.
- [ ] Отображение ограничений: не все сортировки/группировки возможны без дополнительной памяти или временного хранилища.

### 2.3 Parquet Viewer (P0–P1)

### 2.4 Local Data Playground на DuckDB-WASM (P1)

- [ ] Подключить DuckDB-WASM с ленивой загрузкой.

- [ ] Результаты отображать виртуализированной таблицей с ограничением числа строк на экране.
- [ ] Поддержать отмену долгих запросов и отображение времени выполнения.
- [ ] Экспорт результата в CSV/JSON/Parquet (где поддерживается).
- [ ] Понятно объяснять лимиты памяти и различия между браузерами.
- [ ] Проверить выбранный вариант DuckDB-WASM с требованиями к CORS/COOP/COEP и поддержке threads; обеспечить fallback.

### 2.5 SQLite Explorer (P1)

- [ ] Открытие локального файла `.sqlite`/`.db` через SQLite WASM.
- [ ] Просмотр схемы, таблиц, индексов и данных.

- [ ] Прогресс, отмена, предпросмотр и скачивание результата.

### 3.4 Signatures & Checksums (P2)

## UX и продуктовые задачи (сквозные)

- [x] Каждый инструмент — отдельная понятная страница с одной основной задачей.
- [x] Стандартный шаблон: drag-and-drop/выбор файла → параметры → прогресс → результат.
- [x] Возможность запускать обработку нескольких файлов и видеть ошибки по каждому.
- [x] Единый дизайн результатов: copy, download, clear, повторный запуск.
- [ ] При использовании WASM показывать статус загрузки модуля отдельно от обработки файла.
- [x] Помечать инструменты «обработка локально», не обещая абсолютную конфиденциальность браузерной среды.
- [ ] Объяснять браузерные ограничения (CORS, память, доступ к файловой системе, многопоточность).
- [x] Добавить на страницы тяжёлых инструментов примеры входных данных и типовых сценариев.
- [x] Проверить доступность клавиатурой и работу на мобильных устройствах (с ограничениями по объёму файлов).

## Приёмка и производительность

- [ ] Проверка результата по эталонным тестовым данным для каждого алгоритма и формата.
- [ ] Проверка нулевых, повреждённых, экстремально больших файлов и некорректных параметров.
- [ ] Проверка отмены, повторного запуска и отсутствия утечек памяти после нескольких операций.
- [ ] Прогон benchmark на 10 МБ / 100 МБ / 1 ГБ / 5 ГБ (где позволяет окружение).
- [ ] Сравнение throughput и peak RAM в Chrome, Firefox и Edge.
- [ ] Зафиксировать допустимое время первой загрузки WASM и размер модулей.
- [x] Проверить, что при запуске тяжёлой задачи интерфейс остаётся отзывчивым.
- [x] Проверить, что при новой публикации PWA обновляет JS/WASM без конфликтов устаревшего кеша.

## Предлагаемая последовательность релизов

- [ ] **R1 — Processing Core + File Hash Calculator.** Проверка потоковой архитектуры на реальном большом файле.
- [ ] **R2 — Large JSON/JSONL Explorer + Large CSV Explorer.** Работа с большими текстовыми данными.
- [ ] **R3 — Parquet Viewer + DuckDB-WASM Playground.** Анализ табличных данных SQL-запросами в браузере.
- [ ] **R4 — Log Analyzer + SQLite Explorer + Data Format Converter.** Рабочие сценарии backend/Data Engineering.
- [ ] **R5 — Binary Analyzer + Diff + Compression Benchmark.** Высокопроизводительные файловые инструменты.
- [ ] **R6 — Security Extensions + Image/PDF Enhancements.** Расширение существующего каталога.

---

**Правило приоритизации:** сначала функции, которые трудно или неудобно выполнять обычным JavaScript на больших файлах; затем переиспользуемые инструменты для разработчиков; простые конвертеры добавлять только при реальном спросе.
