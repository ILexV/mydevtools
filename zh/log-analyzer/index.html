      大型日志分析器完全在浏览器中检查生产日志。它支持 Serilog JSON 和紧凑日志事件格式、普通 .NET 文本、Nginx 访问和错误日志、通用 NDJSON 以及纯文本，无需上传运维数据。
      详细功能
      分析器通过 Web Worker 每次读取一个大小受限的分块，并且仅保留稀疏文件偏移量和大小受限的聚合计数器。它会提取时间戳、严重性、来源、请求或关联 ID、渲染后的消息、消息模板和异常类型。筛选时会重新扫描完整源文件，而虚拟表格仅请求一小页可见数据。格式错误的结构化行仍会显示并计入统计，而不会静默消失。
      


      导出时会重新扫描完整的筛选结果，并使用原始的 LF、CRLF 或 CR 终止符流式输出原始 UTF-8 行字节。界面会显示 Serilog 渲染后的 @m 文本，而 @mt 仍作为热门消息计数的分组键。任何输入或结果都不会存储在 localStorage 中。
      实用示例
      Serilog CLEF： {"@t":"2026-10-17T10:01:00Z","@l":"Error","@mt":"Payment failed for {OrderId}","@m":"Payment failed for 17"} 会将变化的订单 ID 归入同一个模板。
      


      Nginx 访问日志： 根据 HTTP 状态码类别为组合日志请求分配严重性。
      


      关联搜索： 输入请求 ID 以筛选跨来源的事件，然后导出每一条匹配的原始行。
      如何使用此工具
      1. 1
        选择格式
        普通文件可使用自动检测，也可以明确选择 Serilog/.NET、Nginx、JSON Lines 或文本。
      2. 2
        打开日志
        拖放一个本地文件，并查看精确的字节数、已用时间和吞吐量。取消操作会销毁未完成的 Worker 会话。
      3. 3
        筛选和检查
        组合使用包含边界的时间范围、严重性、来源、请求/关联 ID 和全文搜索。浏览虚拟结果表格，并选择一行以查看原始文本。
      4. 4
        导出
        下载完整的筛选结果。Worker 会重新扫描原始文件，并以背压方式流式输出所有匹配项。
      提示和最佳实践
        

      • 如果不希望将任意 JSON 对象解析为 Serilog，请明确选择 JSON Lines 预设。
        • 

      • 格式错误计数是指不符合所选结构化预设的行；通用文本会接受每一行有效的 UTF-8 文本。
        • 

      • 未选择任何严重性时，结果为空。时间范围会排除无法解析出时间戳的记录。
        • 

      • 为确保内存安全，聚合标签和时间戳分钟存在基数限制，但总计数、筛选、分页和导出仍然精确。
        • 

      • 全文搜索会匹配解码后的确切原始行，且不区分大小写。
        •

      结构化数据
      • {}JSON 格式化在浏览器中格式化、压缩和校验 JSON：支持 2/4 空格或制表符缩进、递归排序键、大数字原样保留，可打开和保存 .json 文件。
      • TSJSON 转 TypeScript 转换器根据 JSON 示例生成 TypeScript interface 或类型别名：嵌套类型、合并数组元素、可选字段、export 关键字。在浏览器中运行。
      • J{}大型 JSON / JSONL 浏览器在本地打开、索引、搜索和导出大型 JSON 与 JSONL 文件，提供虚拟表格、惰性树和精确数字。
      • CSV大型 CSV/TSV 浏览器在本地打开、筛选、检查和导出超大型 CSV 或 TSV 文件，并通过增量解析和虚拟化表格保持流畅操作。
