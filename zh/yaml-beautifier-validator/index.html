YAML 格式化/验证器

校验 YAML 并将其重新格式化为 2 空格缩进的整洁块样式；错误会显示行号和列号。通过 WebAssembly 在本地运行。

输入内容和文件始终留在浏览器中

YAML 输入

在此粘贴 YAML，即可重新格式化或检查语法错误。

在编辑器中按 Tab 键可缩进。按 Esc 再按 Tab 可移出编辑器。

输出

格式化后的 YAML 或校验结果将显示在这里。

检查 YAML 文件的语法错误，并以统一的块样式重写。解析和格式化在浏览器中由一个编译为 WebAssembly 的小型 Rust 库完成，该库仅在你首次点击格式化或验证时加载。

详细功能

验证 只解析输入，并给出 “YAML 有效”，或显示第一个错误及其行号和列号，例如 mapping values are not allowed in this context at line 2 column 7。格式化 会解析并重新输出每个文档：映射和列表采用两空格缩进的块样式，[80, 443] 或 {host: localhost} 这样的行内集合会展开为多行，每个文档以 --- 开头。支持用 --- 分隔多个文档的文件。

格式化重写的是数据而不是文本，因此有些内容会被规范化：注释会被删除，空值变为 ~，YAML 1.1 工具会当作布尔值读取的单词（yes、no、on、off）会加上引号，例如 flag: "yes"。键的顺序保持不变。如果只需要检查语法、希望文件保持原样，请使用验证。

输入编辑器高亮 YAML 并可折叠嵌套块；结果显示在只读的输出编辑器中。粘贴 插入剪贴板中的文本，复制 复制输出内容。你输入的任何内容都不会被存储或上传。

实用示例

行内列表转块样式：ports: [80, 443] 会格式化为 ports:，后面跟着 - 80 和 - 443 两行。

找出缩进错误：name: demo 后面跟一个缩进的 port: 80，会报错 “YAML 无效: mapping values are not allowed in this context at line 2 column 7”。

多个文档：a: 1、---、b: 2 仍是两个文档 —— 输出为 ---、a: 1、---、b: 2。

规范化的值：flag: yes 和空的 empty: 变为 flag: "yes" 和 empty: ~。

如何使用此工具

  1. 1

    添加 YAML

    将其粘贴到 YAML 输入 编辑器中，或点击 粘贴 插入剪贴板内容。

  2. 2

    检查语法

    点击 验证。徽标会显示 “YAML 有效”，否则编辑器上方会出现带行号和列号的错误。

  3. 3

    格式化

    点击 格式化（或在输入框中按 Ctrl+Enter / Cmd+Enter），在 输出 中得到规范化的 YAML。

  4. 4

    复制结果

    点击 复制 将格式化后的 YAML 放入剪贴板。

提示和最佳实践

  • 格式化会删除注释 —— 请保留原始文件，或者对含有重要注释的文件只使用验证。
  • YAML 不允许用制表符缩进；错误位置会指向出问题的那一行。
  • 行号和列号从 1 开始，与大多数编辑器的显示一致。
  • 提交 Kubernetes、Compose 或 CI 配置文件前，请确认 "yes" 这类加了引号的值符合你的工具的预期。
  • WebAssembly 模块会在首次格式化或验证时下载；之后页面离线也能使用。
  • 在输入编辑器中按 Tab 会插入缩进；先按 Esc 再按 Tab 可将焦点移出编辑器。

结构化数据

  • {}JSON 格式化在浏览器中格式化、压缩和校验 JSON：支持 2/4 空格或制表符缩进、递归排序键、大数字原样保留，可打开和保存 .json 文件。
